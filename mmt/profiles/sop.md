# 操作手册模式（把一段演示写成一份能照着做的手册）

这个文件是**写手册的规范**，和 `minutes.md` 是同一类东西：工具自己不会写字，它把材料和这份
规范一起交给助手，助手照着写。

材料只有一份，就是下面那条**时间轴**：每一句话，加上说这句话时屏幕上是什么、说完之后屏幕
变成了什么。形如

```
[0:00:42] shots/shot_000038.png -> shots/shot_000045.png
    Others: Then type a short note in the comment box
```

箭头左边是说话时的画面，右边是这句话做完之后的画面；只有一张就是画面没变。

## 用哪种语言写

**跟着录音走。** 材料开头写了这段录音主要是什么语言，就用那种语言写整份手册。
但界面上的字（按钮名、列名、菜单项、字段名、路径、ID）一律照抄原文，绝不翻译：
按钮叫 `Submit for Approval` 就写 `Submit for Approval`，不要写「提交审批」。

## 步骤怎么切

**一步 = 一个能独立做完的动作**，通常对应一次页面跳转、一次对话框开关、一次保存。
说话人换气不算一步；连着几句话在同一个画面上讲同一件事，合成一步。

整份手册控制在 **5 到 12 步**。超过 12 步说明这场演示该拆成两份手册。

一场演示里讲了两三个不同的流程，还是写**一份**手册，用二级标题分节，不要拆成几份。

## 每一步的形状

```
### 步骤 N · <动作，动词开头>
- 在哪里：<系统 / 页面 / 菜单路径，用界面上的原文>
- 做什么：<点什么、填什么、选什么，字段名照抄界面>
- 看到什么算成功：<做完之后画面上出现了什么>
- 依据：shots/shot_000038.png · 0:00:42 · 「Then type a short note in the comment box」
```

**「依据」这一行是硬要求，每一步都要有。** 它必须指向时间轴里**真实出现过**的图片名和
真实说过的那句话，一个字都不能编。「看到什么算成功」优先引用箭头右边那张图。

指不回任何一张图、也指不回任何一句原话的步骤，不要写进步骤里，放到最后的「提到但没演示」。

## 只有录音、没有画面的时候

材料里会写明这段录音没有录屏。这时候：

- 照样写步骤，但**不要编图片名**，「依据」那一行只写时刻和原话。
- 每一步的「在哪里」只能写说话人真说出口的东西。他说「打开那个链接」而没说是什么链接，
  就写「录音里没说是哪个链接」，不要替他猜一个。
- 手册开头第一句话写明：这份手册只根据讲解写成，没有画面可核对。

## 不许做的事

**不确定就标出来。** 画面被挡住、字太小、说话人自己说错又改口 —— 在那一步下面写
`⚠️ 不确定：<原因>`。宁可留一个问号给人核对，也不要编一个看起来对的步骤。

**说话人推翻了自己，以后面那句为准。** 「算了，这个不用」「等一下，应该先……」——
后面的说法赢，前面那版直接不要，也不要两个都写上。

**不要碰数字。** 金额、工时、比例、日期、行号，原样抄，不换算、不推断、不补单位。

**不要加录音里没有的步骤。** 哪怕你知道这个系统通常还要点一下「确认」，没讲就是没有。

## 产出的形状

第一行就是 `---`，front matter 如下，接着是正文：

```
---
title: <手册名字，一句话说清这是干什么的>
source: <会话名>
lang: <zh 或 en，跟录音一致>
steps: <几步>
shots: <引用了几张图>
unverified: <有几步带 ⚠️>
---
```

正文顺序固定：

1. **这份手册是干什么用的** —— 一段话，说清做完之后得到什么。
2. **开始之前** —— 前置条件：要有什么权限、要打开什么、要准备什么。录音里没提就写「录音里没提」。
3. **步骤** —— 上面那个形状，一步一段。
4. **提到但没演示** —— 说话人提过、但画面上没做的事，列表。
5. **需要人确认的地方** —— 所有 ⚠️ 汇总到这里，写清要问谁或查什么。

## 老实话，写手册时要记住

- 画面是 3 fps 抽的，一闪而过的提示框可能没录到。
- 鼠标移动、拖动滑块这类动作画面上看不出来，只能靠原话。
- 逐字稿本身有错字，尤其英文专有名词。跟画面上的字对不上时，**以画面为准**。
